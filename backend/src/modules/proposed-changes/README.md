# Модуль предлагаемых изменений (ProposedChanges)

## Назначение

Гость — пользователь без прав МОЛ на склад — не может править объект напрямую.
Его правки складываются сюда как предложения, а МОЛ в админке их рассматривает:
принять — изменение применяется к объекту, отклонить — запись удаляется.

## Файловая структура

| Файл | Назначение |
|---|---|
| `proposed-changes.controller.ts` | HTTP-маршруты |
| `proposed-changes.module.ts` | Модуль NestJS |
| `proposed-changes.service.ts` | Создание, выборка и применение предложений |
| `dto/create-proposed-change.dto.ts` | `CreateProposedChangesBatchDto` — пакет изменений |
| `entities/proposed-change.entity.ts` | Сущность `ProposedChange` (таблица `proposed_changes`) |

## Маршруты

Весь контроллер закрыт `JwtAuthGuard`.

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/api/proposed-changes` | создать пакет предложений от текущего пользователя |
| `GET` | `/api/proposed-changes` | предложения по складам МОЛа; `?zavod=&sklad=` сужает до одного склада |
| `POST` | `/api/proposed-changes/:id/approve` | применить предложение к объекту и удалить запись |
| `DELETE` | `/api/proposed-changes/:id` | удалить запись — фронт зовёт после применения или отклонения |

## Ключевые методы сервиса

| Метод | Зачем |
|---|---|
| `createBatch(changes, userId)` | создать пакет предложений одной пачкой |
| `findByMolAccess(molAccess)` | предложения по складам, доступным МОЛу |
| `approve(id, userId)` | применить предложение к объекту |
| `remove(id, manager?)` | удалить запись; при отклонении фото уходит каскадом |
| `removeBatch(ids, manager?)` | то же для нескольких записей |

## Особенности

- **Применение зависит от типа изменения:** `place` меняет местоположение,
  `sn` — серийный номер, `comment` дописывает историю объекта, `photo`
  привязывает фото к объекту (в предложении оно лежит с `object_id = 0`),
  `qr_code` — QR-код.
- **Модуль импортирует `PhotosModule` и `QrCodesModule`** — без них применение
  `photo` и `qr_code` было бы невозможно.
- **`findAll()` в сервисе не вызывается** — контроллер всегда идёт через
  `findByMolAccess`. Метод остался, судя по всему, от ранней версии.
- **Удаляет запись фронтенд.** Сервер тоже удаляет её внутри `approve`, а
  `DELETE` нужен для случая «отклонить»: тогда не применяется ничего, запись
  просто исчезает.
