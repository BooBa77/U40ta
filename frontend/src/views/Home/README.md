# Модуль Home - Главная страница приложения

## Обзор

Модуль `Home` — главная страница приложения U40TA. Объединяет функциональность для трёх ролей: МОЛ (материально-ответственное лицо), Ревизор и гость. Обеспечивает QR-сканирование объектов, работу с ведомостями МОЛ, управление инвентаризационными книгами, доступ МОЛа к строкам инвентаризации и офлайн-режим.

## Структура компонентов

### Основные компоненты

1. **Home.vue** — корневой компонент, оркестрирует все секции и модалки
2. **StatementsSection.vue** — список ведомостей МОЛ с автопроверкой почты
3. **InventoryBooksSection.vue** — список инвентаризационных книг ревизора
4. **InventoryBookEditModal.vue** — универсальная модалка создания/редактирования книги
5. **MolInventoryModal.vue** — модалка просмотра строк инвентаризации для МОЛа
6. **BottomMenu.vue** — фиксированное нижнее меню с кнопками действий
7. **FlightModeToggle.vue** — переключатель офлайн/онлайн режима

### Вспомогательные компоненты

- **ObjectFormModal.vue** — модалка редактирования объекта (по QR-коду или клику)
- **PWAInstallButton.vue** — кнопка установки PWA (логика перенесена в BottomMenu)

## Роли и доступ

| Роль | Видит на Home | Может делать |
|------|---------------|--------------|
| МОЛ | StatementsSection, секция "Инвентаризация" (если расшарены строки), кнопка "МОЛ" | Открывать ведомости, удалять ведомости, просматривать строки инвентаризации |
| Ревизор | InventoryBooksSection, кнопка "Новая инвентаризация" | Создавать/редактировать книги, управлять командой, расшаривать для МОЛов |
| МОЛ + Ревизор | Обе секции, все кнопки | Весь функционал |
| Гость | QR-сканер | Сканировать QR-коды объектов |

## Функциональность

### 1. Ведомости МОЛ

**StatementsSection.vue:**

- Список спарсенных ведомостей текущего МОЛ (фильтрация по `user_id` из JWT)
- Открытие ведомости по клику → `/statement/[receivedAt]`
- Автопроверка почты каждые 5 минут
- Ручная кнопка проверки почты
- Удаление ведомости (только онлайн)
- Ведомости парсятся сразу при получении письма, файлы не хранятся на диске

### 2. Инвентаризационные книги ревизора

**InventoryBooksSection.vue:**

- Список книг, доступных ревизору (через `revisor_access`)
- Открытие книги → `/inventory-book/[id]`
- Кнопка "Редактировать" (только для владельца, `isOwner: true`)
- Кнопка скрыта в офлайн-режиме
- Обновление через SSE: `inventory-book-changed`, `access-changed`

**InventoryBookEditModal.vue:**

- Создание: название + выбор batch'ей (с удалением) + выбор ревизоров
- Редактирование: название + состав книги (batch'и с ⚠ для подтверждённых) + команда + задействование МОЛов
- Предупреждение при снятии batch'а с `isOkManual`/`isOkAuto`
- Доступ ревизоров: список ревизоров с чекбоксами (текущий пользователь исключён)
- Задействование МОЛов: список МОЛов-кандидатов (по пересечению mol_access со складами книги)
- Одна кнопка "Применить"/"Создать" для всего: название, состав, доступ ревизоров, доступ МОЛов
- При создании: сначала книга → получен `id` → затем записи в `revisor_access`

### 3. Инвентаризация для МОЛа

**Секция на Home.vue:**

- Отображается между секциями ревизора и ведомостями МОЛ
- Видна только онлайн, если есть строки в `inventory_book_mol_access` для текущего пользователя
- Кнопка "ИНВЕНТАРИЗАЦИЯ" с красными буквами и мигающим жёлтым фоном
- Обновление через SSE: `inventory-book-changed`, `objects-changed`

**MolInventoryModal.vue:**

- Таблица строк, доступных МОЛу через `inventory_book_mol_access`
- Колонки (по экранам):
  - Экран 1: Инв. номер, Партия, Наименование
  - Экран 2: Территория, Позиция, Кабинет, Пользователь
  - Экран 3: Подтверждено, Дата
  - Экран 4: Комментарий
- Цветовая индикация:
  - Зелёный — подтверждено (isOkManual или isOkAuto)
  - Красный — объект не найден в системе (idObject = 0)
  - Серый — isActual = false (скрыты по умолчанию)
- Чекбокс "Не актуальные" для отображения скрытых строк
- Фильтры по клику на заголовки колонок
- Клик по строке с объектом → ObjectFormModal
- Переключение экранов колонок кнопками "← Влево" / "Вправо →"

### 4. Нижнее меню

**BottomMenu.vue** — фиксированное меню, видно только авторизованным:

| Позиция | Кнопка | Кто видит | Скрыта в офлайне |
|---------|--------|-----------|-------------------|
| Левая | "Новая инвентаризация" | Ревизор | Да |
| Центр | "МОЛ" | МОЛ | Нет |
| Правая | "PWA" | Все (если доступна установка) | Да |

### 5. Офлайн-режим

- Включение: кэширование данных в IndexedDB через `offline-cache-service`
- Выключение: синхронизация изменений + очистка кэша
- Ревизор: список книг отображается, кнопка "Редактировать" скрыта
- МОЛ: список ведомостей отображается, удаление скрыто, секция "Инвентаризация" скрыта
- SSE не подключается в офлайне

### 6. QR-сканирование

- Сканирование камерой или переход по ссылке `/scan/:qrCode`
- Поиск объекта через `qrService`
- Открытие `ObjectFormModal` с данными объекта
- Поддержка онлайн и офлайн режимов

## SSE-события

| Событие | Отправитель | Получатель | Действие |
|---------|-------------|------------|----------|
| `inventory-book-changed` | Бэкенд | Home.vue, InventoryBooksSection | Обновить список книг, проверить строки МОЛа |
| `access-changed` | Бэкенд | Home.vue | Перепроверить роли |
| `user-data-updated` | Бэкенд | Home.vue | Обновить аббревиатуру |
| `objects-changed` | Бэкенд | Home.vue, MolInventoryModal | Проверить строки инвентаризации МОЛа |

## Интеграция с API

### МОЛ
- `GET /api/statements` — список ведомостей
- `DELETE /api/statements?receivedAt=...` — удаление ведомости
- `POST /api/email/check` — проверка почты (автотаймер)
- `GET /api/inventory/mol/items` — строки инвентаризации для МОЛа

### Ревизор
- `GET /api/inventory/books` — список книг
- `GET /api/inventory/books/:id` — книга
- `GET /api/inventory/books/:id/items` — строки книги
- `POST /api/inventory/books` — создать книгу
- `PATCH /api/inventory/books/:id` — обновить книгу
- `DELETE /api/inventory/books/:id` — удалить книгу
- `GET /api/inventory/books/:id/access` — список доступа ревизоров
- `POST /api/inventory/books/:id/access` — добавить ревизора
- `DELETE /api/inventory/books/:id/access/:userId` — убрать ревизора
- `GET /api/inventory/books/:id/mol-candidates` — МОЛы-кандидаты
- `GET /api/inventory/books/:id/mol-access` — расшаренные МОЛы
- `POST /api/inventory/books/:id/mol-access` — расшарить для МОЛов
- `DELETE /api/inventory/books/:id/mol-access/:userId` — снять доступ МОЛа
- `GET /api/inventory/batches` — список batch'ей
- `GET /api/inventory/batches/items` — строки batch'а
- `DELETE /api/inventory/batches` — удалить batch

### Пользователь
- `GET /api/users/me/abr` — аббревиатура
- `GET /api/users/me/has-access-to-statements` — проверка МОЛ
- `GET /api/users/me/is-revisor` — проверка ревизора
- `GET /api/users/revisors-list` — список ревизоров (для выбора коллег)

### Офлайн
- `GET /api/offline/data` — загрузка данных для кэширования
- `POST /api/offline/sync` — синхронизация изменений

## Сервисы фронта

- `statement.service.js` — онлайн/офлайн работа с ведомостями МОЛ
- `email.service.js` — проверка почтового ящика
- `inventory-book.service.js` — онлайн/офлайн работа с книгами, доступ ревизоров и МОЛов
- `inventory-statements.service.js` — только онлайн, batch'и ревизора
- `mol.service.js` — игнор-слова, экспорт, строки инвентаризации МОЛа
- `offline-cache-service.js` — кэширование в IndexedDB
- `useCurrentUser.js` — композабл: `userAbr`, `isRevisor`, `fetchUserAbr`, `fetchIsRevisor`

## Стили

- Tailwind CSS на всех компонентах
- Кастомные анимации в scoped style (мигание кнопки "Инвентаризация")

## Меры безопасности

- JWT-авторизация на всех эндпоинтах
- Каждый МОЛ видит только свои ведомости (фильтрация по `user_id` из JWT)
- Каждый МОЛ видит только строки инвентаризации из `inventory_book_mol_access`
- Проверка `idOwner === userId` на бэке для редактирования/удаления книг
- Проверка `mol_access` для ведомостей МОЛ
- Проверка `revisor_access` для книг ревизора
- Frontend: кнопки управления скрыты по ролям и флагам владения
